# jedf 形式仕様（v0.1）

この文書は、jedf の形式として確定した内容だけを記録する。設計の背景や未決定の論点は `docs/idea/jedf_idea.md` にある。内容は v0.1 の実装（2026-11-22 確定）に基づく。

## 1. 文書モデル

文書はブロックの列である。各ブロックは意味の単位を表し、描画方法は含まない。

| ブロック | 内容 |
| --- | --- |
| heading | 見出し。レベル（整数）とランの列 |
| paragraph | 段落。ランの列 |
| section | 見出しランの列と、子ブロックの列を持つコンテナ |
| list | 順序つきかどうか（真偽値）と、項目の列。各項目はブロックの列 |
| table | 行の列。各行は header フラグ（真偽値）とセルの列を持ち、各セルはブロックの列。セル結合はない |
| code | コード。テキストと、任意の言語名 |
| math | 数式ブロック。TeX ソースを文字列としてそのまま保持する |
| figure | 図。参照先（src）、代替テキスト（alt）、任意のキャプション（ランの列） |
| footnote | 脚注。id（文字列）とブロックの列 |
| page_break | 改ページのヒント。内容を持たない |

### ランとマーク

段落や見出しのテキストは、ランの列で表す。ランはテキスト文字列とマークの組である。マークは次の5種類で、いずれもラン単位で付け外しする。入れ子にはならないため、範囲の重なりは構造として表現できない。

| マーク | 値 | 意味 |
| --- | --- | --- |
| emphasis | 真偽値 | 強調 |
| strong | 真偽値 | 強い強調 |
| code | 真偽値 | コード（等幅） |
| math | 真偽値 | インライン数式。テキストは TeX ソース |
| link | 文字列 | リンク先 URL |

## 2. 標準形式（JSON）

標準形式は、文書モデルを JSON で表したものである。文書全体は次の形のオブジェクトとする。

```json
{"type":"document","version":1,"blocks":[ ... ]}
```

- `version` は形式の版で、v0.1 では `1`
- エンコーダは、各オブジェクトのキーを `type` から始めてこの仕様の表の順序で出力する。パーサはキーの順序に依存してはならない
- 未知のキー、重複したキー、未知のブロック種別はエラーとする

各ブロックの JSON 形は次のとおり。`language` と `caption` は `null` を許す。

| type | フィールド |
| --- | --- |
| heading | `level`（数値）、`content`（ランの配列） |
| paragraph | `content`（ランの配列） |
| section | `title`（ランの配列）、`blocks`（ブロックの配列） |
| list | `ordered`（真偽値）、`items`（ブロック配列の配列） |
| table | `rows`（`header` と `cells` を持つオブジェクトの配列。`cells` はブロック配列の配列） |
| code | `text`（文字列）、`language`（文字列または null） |
| math | `source`（文字列） |
| figure | `src`（文字列）、`alt`（文字列）、`caption`（ランの配列または null） |
| footnote | `id`（文字列）、`blocks`（ブロックの配列） |
| page_break | なし |

ランは `{"text":"..."}` を基本形とし、マークがある場合のみ `marks` オブジェクトを付ける。`marks` には、既定値（真偽値なら false、link なら無し）でないエントリだけを含める。

```json
{"text":"example","marks":{"emphasis":true,"link":"https://example.com"}}
```

ファイルの拡張子は `.jedf`、メディアタイプは `application/vnd.jedf+json` とする。

## 3. 検証規則

検証は、構造規則とリソース上限の2種類からなる。検証結果は問題の列で返し、問題がなければ文書は正しい。各問題は、安定したコード、文書内の位置を示すパス、メッセージを持つ。パスは `blocks[2].runs[0]` のような形で、リスト項目は `.items[i]`、表のセルは `.rows[r].cells[c]` を使う。検証は入力が不正でも例外を投げず、見つけた問題をすべて返す。

### 構造規則

| 規則 | コード |
| --- | --- |
| 見出しレベルは 1 から 6 の間 | `structure.heading_level` |
| 図の alt が空でない | `structure.figure_alt` |
| 脚注の id が空でなく、文書内で重複しない | `structure.footnote_id` |
| テキストが空のランがない | `structure.empty_run` |
| リンク先のスキームが許可範囲内（第4節） | `structure.link_scheme` |

### リソース上限（既定値）

| 項目 | 既定値 | コード |
| --- | --- | --- |
| 入れ子の深さ | 32 | `limit.depth` |
| 総ブロック数 | 10000 | `limit.blocks` |
| ブロックあたりのラン数 | 1000 | `limit.runs` |
| 1つのテキストの長さ（スカラー数） | 100000 | `limit.text` |
| 文書全体のテキストの長さ（スカラー数） | 10000000 | `limit.total_text` |
| 表の行数 | 1000 | `limit.table_rows` |
| 表の列数 | 100 | `limit.table_columns` |
| リストの項目数 | 10000 | `limit.list_items` |

上限は検証する側が変更できる。既定値は参照実装の値である。

## 4. リンク先

リンク先として許可するのは、相対参照、フラグメント、およびスキームが http、https、mailto のいずれかである URL とする。スキームの判定では、`/`、`?`、`#` より後ろに現れるコロンはスキームの一部とみなさない。

## 5. テキスト

テキストの長さは Unicode スカラー値の個数で数える。Unicode 正規化は行わない。テキストは書かれたまま保持し、文書の同一性はスカラー値の列で判定する。正規化は、文書を書く側の関心事とする。

## 6. 描画（参照実装の振る舞い）

描画は形式の一部ではないが、参照実装の振る舞いをここに記録する。

### HTML

- 文書全体ではなく、HTML のフラグメントを返す
- section の見出しレベルは入れ子の深さから決める。最上位の section は h2 とし、深くなるごとに1つ下げ、上限は h6
- 表は、先頭行が header 行の場合にその行だけを `thead` に入れ、残りを `tbody` に入れる。先頭以外の header 行は、本文中で `th` セルとして描く
- 脚注は `<aside class="footnote" id="fn-<id>">` として描く
- テキストと属性値はエスケープする。検証で弾かれる範囲外の見出しレベルは、描画側では 1 から 6 に丸める

### Typst

- section の見出しレベルは HTML と同じ規則
- 脚注は `// jedf footnote: <id>` というコメントの後に、その内容のブロックを通常どおり出す
- 数式は TeX ソースをそのまま `$ ... $` に入れる。TeX の記法は Typst の数式記法と互換でない場合があり、そのままでは組版できないことがある（既知の制限）
- コードブロックのフェンスは、内容に含まれるバッククォートの最長列より長くする
- Typst 側の自動変換（`--`、`...`、引用符など）は無効化していない

## 7. コマンドラインツール（参照実装）

| コマンド | 動作 |
| --- | --- |
| `validate <file>` | 検証し、問題があればコードとパスとともに表示する |
| `to-html <file>` | HTML フラグメントを出力する |
| `to-typst <file>` | Typst ソースを出力する |
| `fmt <file>` | 標準形式に整形して出力する |
| `pack <file> <output> [assets...]` | 文書とアセットファイルをコンテナに詰める |
| `unpack <file> <output>` | コンテナから文書とアセットを取り出す |
| `to-cbor <file> <output>` | 文書を CBOR 符号化で書き出す |
| `from-cbor <file>` | CBOR の文書を標準形式で出力する |

終了コードは、正常が 0、文書が不正（検証で問題が見つかった）が 1、使い方・ファイル読み込み・パースのエラーが 2。`to-html` と `to-typst` は生成前に検証し、不正な文書は生成しない。`fmt` は検証しない。`pack` と `to-cbor` は生成前に検証し、不正な文書は書き出さない。`unpack` は文書を取り出し、アセットは文書の出力先のディレクトリにファイル名（パスの最後の要素）で取り出す。空の名前や `..` を含む名前のアセットは取り出さない。

## 8. コンテナ形式

文書とバイナリのアセットを単一ファイルで配布するための形式。バージョンは 1 とする。ファイル拡張子は `.jedfc` とする。

- 先頭にマジック `JEDF`（4 バイト）、形式バージョンとマニフェスト長（いずれもリトルエンディアンの UInt32）が続く
- マニフェストは JSON で、チャンクの一覧（名前、長さ、FNV-1a 64 ビットハッシュの 16 進表記）を順序どおりに持つ
- チャンクのバイト列がマニフェストの直後に同じ順序で並ぶ。オフセットは持たず、長さから順にたどる
- 先頭のチャンクは名前が `document` で、標準形式の文書そのものとする。それ以外はアセットで、名前は空でなく一意でなければならない
- 読み出しでは全チャンクのハッシュを検証する。FNV-1a は偶発的な破損の検出用であり、改ざんの検出には使えない

## 9. CBOR 符号化

標準形式と同じスキーマを CBOR（RFC 8949）で表した第二の符号化。メディアタイプは `application/vnd.jedf+cbor` とする。

- 使うのは、符号なし整数、負の整数、テキスト文字列、配列、マップ、真偽値、null のみとする。バイト文字列、タグ、浮動小数点数、不定長は使わない
- マップのキーは標準形式と同じ固定順で出し、整数の引数は最短形式にする。等しい文書は等しいバイト列になる
- 読み取りでは最短でない形式も受け付けるが、不定長、タグ、バイト文字列、重複したキー、末尾の余分なバイト列はエラーにする
